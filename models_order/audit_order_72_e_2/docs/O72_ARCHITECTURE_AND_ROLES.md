# ORDER72 emergent v0 — roles and invariants

## Causal separation

The system is split into two fundamentally different classes.

**Information-processing components**: fingerprinting, constraints, memory, WM representations, WM predictions, search heuristics, routing and experiment priority.

**Truth-bearing components**: public experiment execution, external verification and exact public-objective certification.

The second class is forbidden from reading a WM prediction as truth.

## Exact condition

A public answer may be certified only when the problem contract provides a certified public objective and the evaluation covers every legal root action (or an explicitly equivalent mathematical certificate exists). Ties produce an unresolved status.

## Search condition

When exact closure is unavailable, ORDER72 may use a WM to prioritize exploration. It must retain the distinction `proposed != verified`.

## WM portfolio

The default portfolio contains O65 and O70-att1. They are deliberately complementary rather than pretending to be identical models.

## Scaling criterion

The correct comparison is decision-relevant utility per resource:

`marginal utility / extra compute`

not parameter count alone.
