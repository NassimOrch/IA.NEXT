# Phase 6 — Audit des 25 règles rouges anti-triche

**Échelle :** PASS = contrôle explicite disponible; PARTIEL = mesure réelle mais couverture insuffisante; RISQUE/ÉCART = la contrainte stricte du prompt n'est pas complètement satisfaite. Cette table ne transforme pas les vérifications de code en preuve absolue d'absence de fuite. La suite d’audit indépendant v6 comprend 49 contrôles : elle inclut la recomputation des métriques depuis les prédictions, les assertions sur la boucle RBF-R1, l’extension digits à dix classes et la provenance web. Le journal initial v6 en échec est conservé; le contrôle final corrigé a terminé avec 49/49 et code de sortie 0.

## Règles supplémentaires découvertes

26. Une fingerprint calculée à partir d'un résidu n'est pas indépendante de l'observation qui la génère; on ne doit pas la compter comme une mesure supplémentaire.

27. Un résultat d'ensemble entrée-sortie, même exact sur un échantillon, n'identifie pas les paramètres internes ni la mécanique génératrice.

28. Un update sur une observation « trompeuse » est une intervention expérimentale connue de l'auditeur, mais cette vérité de corruption ne doit jamais être donnée au learner lors du calcul d'update. Dans les stress-tests, seul l'auditeur connaît le masque de corruption.
